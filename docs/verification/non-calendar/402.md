## Public read contract

```swift
public func historyReport(
    from: DayKey,
    through: DayKey,
    now: Date = Date(),
    calendar: Calendar = .current
) throws -> HistoryReport
```

The range is ordered, inclusive, and limited to 366 local Gregorian dates. The calendar supplies the time zone. Invalid ranges throw `ThreeError.invalid` before the database read. The entire report is assembled inside one `DatabasePool.read` transaction. The read does not write or post a change signal.

Civil-date enumeration uses a fixed Gregorian calendar independently of the query's local timestamp bounds. This retains dates when DST removes local midnight or a time-zone transition skips a whole date. A skipped date has an empty timestamp interval and cannot borrow the next day's sessions. Native day labels format the stored civil date independently of local midnight.

`HistoryReport` is Codable, Hashable, and Sendable. It contains `from`, `through`, `takenAt`, `timeZoneIdentifier`, `plannedMetrics`, `dateAttribution`, `totals`, `months`, and `days`.

- `HistoryMonth` contains its Gregorian `yyyy-MM`, included bounds, day count, totals, and category totals. Partial months retain their actual bounds.
- `HistoryDay` contains its date, optional plan, totals, category strips, task details, and session details. Every requested date is present, including empty days.
- `HistoryTask` preserves the stored task, optional category, current planned date, steps, tags, session IDs, day-attributed focus, and derived planned seconds.
- `HistorySession` preserves the full stored session and its reflection, optional task and category, tags, and actual seconds.
- `HistoryTotals` contains planned seconds, focus seconds, break seconds, eligible planned task count, done task count, focus session count, and break session count.

Days and months are oldest first. Sessions are ordered by start and ID. Tasks retain position order, followed by references from sessions whose tasks are now planned elsewhere. Category order follows stored position and ID. Missing task or category references remain optional rather than removing the session. Stored IDs remain available on the source records.

## Accounting definitions

`Session.elapsed(at: now)` supplies every actual duration. Focus totals exclude breaks. Break duration remains separately available. Sessions belong entirely to their start date in the report time zone, including cross-midnight sessions. Changing the local time zone can change that date. Plan dates remain stored `DayKey` values.

Historical pause placement is unavailable. The report neither splits sessions across dates nor synthesizes pause intervals. A running or paused session is frozen at `takenAt`. Later recovery work must continue to update `Session.elapsed`; the report has no parallel trim calculation.

`plannedMetrics` is `derivedFromCurrentTaskRows`. Eligible planned tasks belong to that day's nondeleted plan, are not deleted, and are neither dropped nor carried. Their current block lengths supply planned seconds. Done count uses those same eligible tasks. This is a derived current-record denominator, not a commitment-time snapshot. Task and session statuses are the currently stored values. No historical status timeline is inferred.

`HistoryTask.focusSeconds` includes only sessions starting on that report day. It is not lifetime task focus. A session reference from another planned day adds no planned seconds to the session's day. Carry copies remain distinct IDs, and original sessions remain on their source. Archived and soft-deleted categories, tasks, plans, and tags remain readable. Missing ratings and outcomes remain nil.

For trends, global focus comes from `report.totals.focusSeconds`. Per-tag focus can group focus sessions by `HistorySession.tags`. A session with multiple tags belongs to each tag but contributes once to the global total. Category strips contain focus only, with planned seconds separately available. Unknown categories retain a neutral bucket.
