## Store contract

`closeDay(_:now:pendingRecovery:)` returns a Codable `DayCloseResult`.
The operation closes a nonempty, live, committed plan when every live task is resolved or its configured local close time is due.
Draft, empty, and future plans stay editable. A legacy closed plan without a saved summary returns `notEligible(.legacyClosed)`.
The implementation does not invent that plan's close time or summary.

Running focus, including paused focus, and pending reflections defer close when their session starts on the day or their task belongs to the plan.
`pendingRecovery` runs on the same database connection and transaction as the close decision.
The default callback returns false because v12 recovery does not exist at this base.
The recovery owner must supply its durable query during integration.

The summary and plan status commit in one transaction. Summary identity is unique by plan and day.
Repeated close calls, concurrent writers, and relaunch return the same frozen summary.
No change notification is posted for an unchanged or deferred close, which avoids reload loops from background checks.

`closeEligibleDays(now:limit:after:pendingRecovery:)` attempts seven days by default and accepts a limit from 1 to 31.
The query considers only committed, nonempty plans through the current local day.
`DayCloseBatch.nextAfter` permits the next check to continue past deferred days.
When it is nil, the next check starts from the oldest outstanding plan again.
The cursor needs no durable storage. Restarting from nil is safe because closed plans are excluded and every close is idempotent.
The batch is one transaction. An error rolls back that entire batch.

`dayCloseStatus(for:now:pendingRecovery:)`, `dayCloseSummary(for:)`, `recentDayCloses(limit:)`, and `dayCloseReview(for:)` are read-only.
Recent summaries are bounded to 1 through 366 rows.
Reading a review never creates a destination plan.

## Frozen accounting and prospective evidence

The summary freezes original task outcomes, planned minutes, focus sessions, known break decisions, and focus seconds before carry decisions change the source status.
It stores dedicated Codable outcome records rather than live Session or FocusTask models, so v12 session fields do not break existing summary decoding.
Focus seconds use `Session.elapsed(at:)` and exclude breaks and pauses.
Session attribution remains the session's local start day, including cross-midnight work.
No historical pause intervals are invented.

`planCommitment(for:)` returns a prospective snapshot captured atomically on the first draft commitment.
Explicit commit, committed `setPlan`, and implicit commitment by `startFocus` use the same hook.
The snapshot stores the original active task IDs and planned minutes.
Repeated commit, later edits, drops, additions, and replanning do not replace that snapshot.
Pre-v11 committed plans retain nil snapshots even when recommitted after upgrade.

`DayCloseSummary.plannedMinutes` uses the snapshot when one exists.
For a legacy plan it derives the total from the frozen live task rows, excluding dropped and carried tasks.
The view labels that legacy basis as derived.
`doneCount` counts all tasks done at close.
`committedDoneCount` counts only originally committed task IDs that are done at close, and is nil when the commitment is unknown.
The exact commitment denominator is `commitment.tasks.count`, including originally committed tasks later dropped.

`finishFocus` has a new defaulted `breakDecision` argument.
A break continuation records taken, and a task continuation records skipped, in the same transaction as the reflection and continuation.
A plain stop remains unknown unless the caller explicitly supplies `.skipped`.
A conflicting decision throws and rolls back the finish and continuation.
Deferred reflection defaults, ordinary stops, and legacy sessions do not acquire invented decisions.
`skippedBreakCount` is nil if any focus session in the summary lacks a recorded decision.
The stored `breakDecisions` array also permits future reads to report known decisions with their actual denominator.

## Carry and dismissal contract

Existing `carryTask(_:to:now:)` and `pushToTomorrow(_:now:)` signatures remain callable.
Their narrow transaction accepts open work from either an editable or closed source.
`requireEditable` remains unchanged for ordinary edits and destination plans.
The destination must be later than the source, editable, and within the five-task cap.
The source cannot be running or awaiting a saved reflection.

Acceptance copies the source with a new ID, todo status, no scheduled start, and `carriedFromTaskId` pointing to its immediate source.
The unique lineage index and durable `carryDecision` row prevent duplicate copies.
The copy keeps category identity, strictness, notes, Linear reference, source, tag identities including archived tags, and steps including done state.
Category references remain intact even when the category is soft-deleted.
The original task retains its ID and sessions and becomes carried only after all copy writes succeed.
A failure rolls back the destination plan, task, tags, steps, decision, and source transition.

Repeated acceptance to the same destination returns the existing copy ID, including after relaunch.
Acceptance to a different destination after success throws.
Old carried rows without recorded lineage remain unknown and are not inferred by title or timestamp.

`dismissCarry(_:now:)` writes a durable dismissed decision and marks the source dropped in a narrow transaction.
The source stays on its original day with its metadata and history intact.
This keeps existing Inbox and `get_carryover` reads from offering it again without changing their contracts.
The operation does not route through ordinary closed-day editing and does not change the frozen summary.
Repeated dismissal returns the original decision. Dismissal after acceptance and acceptance after dismissal throw.
Competing acceptance and dismissal converge on exactly one durable decision.
