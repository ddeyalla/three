## Behavior and design

`NotchScreen` captures public screen geometry. `NotchGeometry` accepts only a positive top safe inset with two nonempty, ordered auxiliary top areas inside the screen. The panel fits completely within the visible frame and below the safe band, with an 8pt gap. Coordinates remain global, including negative origins. A supported built-in display takes precedence over other supported displays. Missing or unsafe geometry produces no panel.

The 360 by 144pt native glass panel shows the current task, category, time, Pause or Resume, Finish, Open Three, and Hide. Titles truncate with full-title help. Native glass buttons retain their focus indicators. No authored animation runs, including with Reduce Motion enabled.

The alternatives considered were controls beside the camera, a panel below the safe band, and the existing MenuBarExtra alone. Side controls compete with system menus and vary with camera geometry. The chosen panel stays below the entire safe band and leaves both auxiliary areas untouched. MenuBarExtra remains the fallback on ordinary externals and unsupported geometry. There is no simulated hardware notch.

`AppModel.snapshot` remains the session source. `NotchView` reads `model.now` only to display `Session.remaining(at:)`. The controller observes snapshot, reflection, and preference changes without a timer. It listens for screen changes, wake, active Space changes, and app activation changes. The panel joins Spaces and uses `fullScreenAuxiliary`. These AppKit settings require native acceptance.

Automatic presentation uses a nonactivating NSPanel and `orderFrontRegardless()`. It never calls `makeKeyAndOrderFront()` automatically. An explicit `showControls()` command makes the panel key. Clicking native controls also allows keyboard interaction. The panel cannot become the main window. Escape or Hide suppresses the current session's presentation. A new session or explicit Show Controls can present again.

Breaks, no running session, a reflection, a disabled preference, or loss of supported geometry hide the panel. A model refresh does not repeatedly reorder an already visible panel. Shutdown removes notification observers and hides the panel. `start()` and `stop()` are idempotent.

`NotchCommands` checks the displayed session ID, running state, and focus kind before Pause or Finish. The production binding reloads AppModel before that check. Pause and Resume call `model.togglePause()`. Finish calls `model.finishEarly()`, so the existing reflection controller owns the result. Open Three invokes only the injected callback. The existing Store command semantics still apply. This unit adds no transaction policy, timer, or reflection flow.

`NotchPreference` persists `notchControlsEnabled` through injected UserDefaults, defaulting to false. `NotchSettingsSection` contains the toggle, the availability explanation, and an explicit Show Controls button. Unsupported displays explain that Three's menu-bar controls remain available. The preference can remain enabled while unsupported, so reconnecting a supported display can restore presentation.

## Parent integration hooks

Retain one `NotchController` for the app lifetime, alongside the existing AppModel. Start it at app startup, including a launch with only the menu-bar item. Do not tie `stop()` to closing the main window.

The exact construction and lifecycle API is:

```swift
let openMainWindow = openWindow
let controller = NotchController(model: model, openMain: {
	openMainWindow(id: "main")
	NSApp.activate()
})
controller.start()
```

Capture the `OpenWindowAction` value rather than the entire owning view or app. `init(model:defaults:openMain:)` accepts an isolated defaults suite for QA. `stop()` removes observers and hides the panel. Deinitialization also calls `stop()`. The AppModel must outlive the controller.

In the Timer Settings form, compose this section with the same model environment:

```swift
NotchSettingsSection(controller: controller)
	.environment(model)
```

The parent can also add `Button("Show Focus Controls", action: controller.showControls)` to an existing app command menu. `showControls()` respects the enabled preference, supported geometry, focus session, and reflection state. It does not enable the option automatically. Do not add a new global shortcut for this unit.

`controller.preference.isEnabled`, `controller.availabilityText`, `controller.placement`, and `controller.isVisible` expose setting and presentation state. Settings must mutate this preference object, rather than introducing another cached boolean. The existing MenuBarExtra and main workspace stay composed independently.

## Independent review race fix

NotchCommands checked session A before dispatch, but unqualified pause/resume could mutate replacement B when another Store process changed the running session before the write.
